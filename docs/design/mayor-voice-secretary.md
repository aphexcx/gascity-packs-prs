## 1. What it is (and is not)

The secretary is a **voice delivery channel for mayor surfaces, plus a structured ear**. It
FaceTime-Audio-calls a founder, reads a pre-compiled brief, walks a queue of questions the mayor
wants answered, captures each answer with a service-generated read-back and an explicit yes,
and lands everything it heard as `gc mail` to the mayor and bead comments. That is the whole
product.

Hard boundaries (mayor constraints, agreed in-thread):

- **Outbound-only v1.** The secretary calls founders (post-evening-brief call + on-demand
  "call me"). No inbound switchboard, no auto-answer, no resident ring-listener. The bridge's
  `answer` verb ships in the vendored artifact but is unreachable through the secretary and
  stubbed out in our helper build (§5.1).
- **Read side: designed mayor surfaces only** — evening brief, handoff ledger, bead queues.
  No direct DB reads, no ad-hoc scripts (memory `agent-surfaces-first-class`). Everything the
  secretary can say is compiled into a frozen Call Brief before dialing (§2.1, §5.2).
- **Write side: mail and comments only.** The secretary NEVER executes. Voice verdicts are
  signal, not authority: each verdict is read back for an explicit yes, logged with the
  founder's transcribed confirm, and delivered to the mayor. Anything irreversible (merges,
  sends, money) happens only after the mayor has the logged confirm — through the existing
  gated surfaces, by the mayor, never by the secretary (§3.3).
- **Voice brain = metered realtime API.** OpenAI Realtime today, paid per token. We do NOT
  build infrastructure on the ChatGPT-OAuth consumer trick (not present in the bridge repo
  anyway). The brain is swappable at a clean seam (§2.3): Anthropic realtime later, or
  ElevenLabs Agents.
- **CN leg is out of v1.** WeCom voice for Taylor in Shanghai is future work in the
  jadegate/Sinan lane (§9, Phase 3). FaceTime-over-data to Shanghai gets one cheap live test
  before anyone builds anything.
- **FaceTime is best-effort, never the only path.** Every brief and every failure degrades to
  Slack (and, if Slack is down, to mayor mail, which is local). A founder who misses the call
  loses nothing but the voice.

Not in scope, any phase currently planned: voice control of city actions ("merge PR 12" as a
command), PSTN/Twilio, always-on inbound switchboard, calling anyone who is not a founder.

## 2. Architecture

### 2.1 Components and boundaries

Four components, one host Mac (§8). The bridge is vendored; the other three are ours. The
governing principle: **the secretary service is the deterministic conversation controller;
the voice brain is a performer.** Every line that carries protocol weight (greeting, consent
question, read-backs, sign-off) is generated by the service and spoken verbatim; the brain
improvises only inside the digest and the open floor, and only from brief content.

```
        designed mayor surfaces                      founder's iPhone
  (evening brief · handoff ledger ·                        ▲
        bead queues)                                       │ FaceTime Audio
              │ read-only, pre-call                        │
              ▼                                            │
  [1] mayor-surface adapter ──frozen Call Brief──▶  [4] secretary service (controller)
                                                     │        │
                                      say()/converse()│ events │ call / probe loop / hangup
                                                     ▼        ▼
                                          [2] voice brain   [3] call bridge (vendored
                                          (realtime API,        facetime-bridge: Swift AX
                                           swappable)           helper + BlackHole audio)
                                                     │        ▲
                                                     └──48kHz MediaStreams──┘
                 gc mail send mayor  ◀── outbox: verdicts, notes, call records ── [4]
                 gc bd comment          ◀──
```

**[1] Mayor-surface adapter (read side).** A compiler, not a live query layer. Before each
call it assembles one **Call Brief** artifact (JSON + rendered text) from the designed
surfaces: the evening brief document, handoff-ledger entries since the last call, and bead
queue summaries the mayor already produces. The brief has: a digest (ordered sections,
escalations first), an **open-words queue** (the questions the mayor wants answered, each with
an id, an answer domain, and an irreversibility tag — §3.1), callee identity, purpose line, a
content hash, and a TTL. The brief is **frozen at compile time**: the brain cannot fetch
anything mid-call. If a surface is unavailable, the section is marked absent and the call
proceeds shorter — the adapter never falls back to raw DB reads.

**[2] Voice brain (provider adapter).** A browser-side module that connects the bridge's
verified 48 kHz mono `MediaStream` (founder's voice in) and returns an output `MediaStream`
(secretary's voice out). v1 = OpenAI Realtime over WebRTC: `pc.addTrack(bridge.incomingTrack)`
for ears, remote track → `bridge.routeOutgoing()` for mouth. The brain exposes controls
(`say`, `converse`, `interrupt`) and emits ordered events (input-turn transcripts, playback
completion, tool calls, health, usage) — §2.3. Its tools are proposals to the service, never
actions: `propose_verdict`, `log_note`, `queue_question_for_mayor`, `request_end_call` (§3).

**[3] Call bridge (vendored kingbootoshi/facetime-bridge, HEAD `ad1948b`).** Reused as the
hard-won piece, with two deliberate deviations noted below. Control plane: the compiled Swift
AX helper (`probe` / `call` / `hangup`; JSON out, fail-closed, one authorized identity per
config file, 0600). Dialing = `facetime-audio://<handle>` + AX press of the single matching
"Click to Call" notification button; state = classified from on-screen AX text; hangup =
graceful Phone-app terminate. Audio plane: BlackHole 16ch/2ch wired into FaceTime's own device
pickers (system default untouched), the 256-line browser module with exact-device matching,
EC/NS/AGC off, stereo→mono proof, and a Web Locks singleton. Two facts about the pinned code
shape our design: (a) **`call` returns as soon as the AX state reaches `dialing` *or*
`connected` and then exits** — it does not wait for an answer and does not report hang-up;
the service supplies the probe loop (§2.2). (b) **The CLI reads exactly one canonical config
path** (`~/.config/facetime-bridge/config.json`) with no selector — so one-founder v1 needs no
patch, and multi-founder needs the small, explicit patch in §5.1. We pin the SHA; the only
carried patches are the config-path override and the `answer` stub (§5.1).

**[4] Secretary service (controller).** A launchd-supervised daemon on the host Mac, running
as its own macOS user. It owns the lifecycle: accept an authenticated call order (§5.5), take
the host-wide single-flight lock, run preflight (§7), compile the brief via [1], open the
browser bridge page, mint an ephemeral realtime session + a per-call capability token for [2],
dial via [3] and drive the probe loop, run the script as a state machine (§3), turn confirmed
verdicts and notes into `gc mail` + `gc bd comment` writes through a durable outbox **as they
happen** (§4), hang up, tear down, deliver the call record, and fall back to Slack/mail on any
failure. It is the only component with gc/bd credentials; the brain has none.

### 2.2 Call lifecycle (race-avoiding order, with the probe loop the bridge doesn't give us)

1. **Order intake.** Validate the call-order envelope (§5.5): issuer is the mayor, callee is in
   the founder table, `order_id` unseen, TTL unexpired, brief hash matches. Persist the order
   with `attempt=1`. Acquire the host single-flight lock (a second order queues; it never
   interleaves).
2. **Preflight** (§7): all `doctor` facts green, `probe` = `idle`, GUI session logged in and
   unlocked, AX + microphone TCC grants present, bridge page healthy, realtime API reachable,
   brief within TTL, inside permitted call hours, free disk above threshold, outbox writable.
3. Open/verify the browser bridge page; `FaceTimeAudioBridge.open()` → verified incoming
   stream.
4. Start the realtime session primed with the fixed system prompt + Call Brief; route model
   output to `bridge.routeOutgoing()`. Brain is idle (no `converse` issued yet).
5. `facetime-bridge call` (45 s command timeout). It returns on `dialing` or `connected`.
6. **Answer wait:** `probe` every 2 s until `connected`, with a 30 s answer deadline (`probe`
   itself is bounded at 8 s and walks five AX trees, so cadence is a Phase-0 tuning item).
   Deadline, `idle`, `ended`, or two consecutive probe failures → `hangup`, outcome
   `unreachable`, Slack fallback.
7. On `connected`: start the **in-call probe loop** (`probe` every 5 s; `ended`/`idle` or two
   consecutive `unknown`/failures = call over) and the **audio-path check** (inbound RMS must
   rise above the silence floor within 10 s of the greeting; a live 48 kHz frame stream that
   is all zeros means the FaceTime pickers or BlackHole drifted — hang up silently, Slack
   fallback, mark degraded).
8. Script runs as the §3 state machine. Confirmed verdicts are written through mid-call (§4).
9. **End:** service-issued sign-off via `say()` → `playback_complete` → `facetime-bridge
   hangup`. Also hangup on: founder hangs up (probe `ended`), hard call cap (15 min), 20 s of
   dead air after a re-prompt, storage failure (§5.4), or watchdog.
10. **Teardown:** `bridge.stop()`, close realtime session, flush outbox, write final call
    record, mail the mayor a call summary (outcome, per-question terminal states, duration,
    measured usage/cost), release the lock.

Dial failures (`PREEXISTING_PROMPT`, `PROMPT_TIMEOUT`, `TARGET_NOT_AUTHORIZED`,
`AMBIGUOUS_ACTION`, `CONFIRMATION_TIMEOUT`, answer-deadline) skip to step 10 with outcome
`unreachable`; the digest and open questions are posted to Slack, so the founder loses nothing.

### 2.3 Provider swappability (the MediaStream seam)

The bridge deliberately ends at "verified 48 kHz mono MediaStream in, MediaStream sink out" —
the video's own framing: *"It literally doesn't matter past that point."* We keep that seam
but the provider contract must be wide enough for the service to be the controller:

```ts
interface VoiceBrain {
  start(o: { incoming: MediaStream; brief: CallBrief; capability: string })
        : Promise<{ outgoing: MediaStream }>;
  // service → brain controls
  say(utteranceId: string, text: string): void;     // verbatim TTS of a service-generated line
  converse(scope: BriefSectionRef): void;             // improvise within ONE brief section only
  interrupt(): void;                                  // cancel current output
  stop(): Promise<UsageReport>;                       // tokens/minutes for the cost record
  // brain → service events, ordered, with ids
  on(ev: 'input_turn',        h: (t: { turnId; transcript; t0; t1 }) => void): void; // transcription stream
  on(ev: 'playback_complete', h: (u: { utteranceId }) => void): void;
  on(ev: 'tool_call',         h: (c: { callId; name; args }) => Promise<ToolResult>): void;
  on(ev: 'health',            h: (s: { connected; latencyMs; lastAudioAt }) => void): void;
  on(ev: 'error',             h: (e: BrainError) => void): void;
}
```

On OpenAI Realtime these map to `response.create` with per-response instructions (`say`),
`conversation.item.input_audio_transcription.completed` (`input_turn` — asynchronous, hence the
confirm-window timeout in §3.2), `output_audio_buffer.stopped` (`playback_complete`), and
function-call events (`tool_call`). ElevenLabs Agents or a future Anthropic realtime API
implement the same interface. The script, verdict protocol, tool contract, outbox, and
supervision are provider-independent; a provider swap is one module plus a config line. No
provider types leak into [1], [3], or [4].

## 3. Call script

### 3.1 Structure

Five fixed movements; the service advances them, the brain performs inside them.

1. **Greeting + consent (service-generated `say`).** Identify as the Gas City secretary
   calling for {founder}, one-line purpose, the disclosure ("this call is transcribed and
   logged for the mayor"), then the consent question: *"OK to continue?"* The service
   evaluates the next `input_turn` with the affirmative grammar (§3.2). Accept →
   `consent_accepted` event, proceed. Refusal, silence, or ambiguity → scripted goodbye,
   hangup, outcome `declined`; nothing from before the consent event is persisted except the
   event itself (§5.4). Setup-time written opt-in is the primary consent record (a founder is
   in the allowlist only with it, §10.3); the in-call question is the per-call record.
2. **Digest (`converse`, one section at a time).** Escalations → decisions pending → status
   deltas → FYI. The founder can say "skip", "next", "more on that one" — the brain may
   reorder/skip within the *current* section; the service decides when the next section opens.
   Nothing not in the brief may be said (§5.2).
3. **Open-words queue (service-driven).** Each item is declared in the brief as:

   ```jsonc
   { "id": "Q2",
     "text": "PR #21 is green with codex sign-off. Merge it, or hold for Taylor?",
     "domain": { "kind": "choice", "options": ["merge", "hold"] },   // or yes_no | freeform_ack
     "weight": "irreversible",        // routine | irreversible
     "bead": "gp-xnc" }               // optional: where the verdict comment lands
   ```

   The service `say`s the question, the brain listens and calls `propose_verdict`, the
   service runs §3.2. The brain cannot skip, reorder, or invent questions; the service asks
   them in brief order and moves on only on a terminal state.
4. **Open floor (`converse`).** "Anything for the mayor?" → `log_note` /
   `queue_question_for_mayor` (plain mail; no confirmation — not verdicts, no authority).
   Quotas: ≤5 notes and ≤5 queued questions per call (§5.3).
5. **Sign-off (service `say`).** Recap by terminal state ("two confirmed, one unconfirmed —
   the mayor will follow up on Slack"), goodbye, hangup (§2.2 step 9). The brain's
   `request_end_call` is honored only after the open-words queue is terminal or when the
   founder's transcript contains a goodbye phrase; otherwise it is logged and ignored.

### 3.2 Verdict capture protocol + read-back grammar

Per-question state machine, **owned and advanced by the service**; the brain only supplies
candidates. `CONFIRMED` is decided by the service from the transcription stream, never by
asking the model whether the founder agreed.

```
PENDING ─ask─▶ ASKED ─propose_verdict(r)─▶ CANDIDATE(r) ─say(readback_id)─▶ READBACK(r)
                                                ▲                               │
                                                │ "yes, but…" / correction      │ playback_complete + next input_turn
                                                └── REVISE (r+1, max r=3) ◀─────┤
                                                                                ├─ affirmative-only ──▶ CONFIRMED(r)   [terminal]
                                                                                ├─ negative / off-domain ─▶ re-ask once, then UNCONFIRMED(denied)   [terminal]
                                                                                ├─ no input_turn within 12 s ─▶ re-ask once, then UNCONFIRMED(no-answer)   [terminal]
                                                                                └─ r > 3 ─▶ UNCONFIRMED(ambiguous)   [terminal]
any non-terminal ── call ends (drop, cap, storage fail, watchdog) ──▶ INTERRUPTED   [resumable, see §4]
```

Rules:

- **CANDIDATE(r)**: `propose_verdict(question_id, candidate)` — the brain's canonicalization
  into the declared domain. Off-domain answers ("ask Taylor first") become a `freeform`
  candidate holding the founder's words verbatim, never forced into an option. Each proposal
  increments the revision `r`; the service stores `candidate_hash(r)`.
- **READBACK(r)**: the **service** renders the read-back from a fixed template and speaks it
  via `say(readback_id, …)` — the brain does not improvise it:

  ```
  "Confirming <Q-topic>: <canonical verdict>. Yes or no?"
  e.g. "Confirming on PR 21: HOLD for Taylor. Yes or no?"
  ```

- **Confirm window**: opens on `playback_complete(readback_id)` and closes on the first
  `input_turn` whose `t0` is after playback completion, or after 12 s (transcription events
  are asynchronous, so the window waits for the completed transcript of that turn, not for
  audio). Turns that started *before* playback completed are ignored for confirmation (they
  may still yield a REVISE if they contain a correction).
- **Affirmative grammar** (service-side, deterministic, applied to the transcript): the turn
  must consist of an affirmative token — `yes`, `yep`, `yeah`, `correct`, `confirmed`,
  `that's right`, `go ahead` — optionally with filler, and **no** negation, conjunction, or
  further content. "Yes, but hold it until Friday" is not a confirm: it is a REVISE with the
  qualification appended, producing `CANDIDATE(r+1)` and a fresh read-back.
- **CONFIRMED(r)** requires all three: playback of `readback_id` for revision `r` completed,
  the bound next turn matched the affirmative grammar, and `r` is still the current revision.
  The record carries `readback_id`, `candidate_hash(r)`, the founder's answer transcript, the
  confirm transcript (`turnId`, `t0/t1`), and `speaker_verified: false` (§5.1).
- Late confirms (a transcript for a turn that arrived after the window closed or after a
  REVISE) are logged and ignored. The secretary never argues a founder into a confirm; after
  the allowed re-ask it moves on and says so in the sign-off.
- `UNCONFIRMED` and `CONFIRMED` are terminal **for this order**: a resumed attempt (§4) never
  re-asks them; unconfirmed items go to the founder on Slack in text form instead.

### 3.3 Why a misheard "merge it" cannot cause a merge — and what is only risk-reduced

The bead's requirement is that a misheard "merge it" must be impossible. Precisely:

**Impossible (structural):**

1. **The secretary executes nothing.** Its only sinks are `gc mail` and `gc bd comment`. There is
   no code path from any tool to a merge, a send, or a payment. Even a CONFIRMED verdict is a
   structured message to the mayor; the action still happens through the existing gated
   surfaces, by the mayor, with the logged confirm as justification. `weight: irreversible`
   items are pre-tagged at compile time so the mayor knows which answers are load-bearing, and
   **irreversible verdicts additionally require a second-channel ack** (the founder reacts or
   replies on the mayor's Slack post) before the mayor acts on them (§5.1, §10.6).
2. **Verdicts attach only to queued questions.** `propose_verdict` with an unknown
   `question_id` is a tool error. An unsolicited "oh, and merge that other thing" can only
   become a `log_note` — plain mail, no verdict semantics.

**Risk-reduced, not impossible (a mis-recorded verdict on a queued question):**

3. The read-back is service-generated from the candidate, so what the founder hears is
   exactly what would be recorded. The confirm is evaluated by the service on the separately
   transcribed founder turn, bound to that specific read-back's playback and revision — not
   the model's own summary of what it heard. Residual risk: the transcription model mishears
   the *answer* and the founder mis-hears the *read-back* in the same way. That is why the
   record carries the transcripts, why speaker identity is labelled unverified, and why
   irreversible items get the second-channel ack. Phase 1 acceptance includes an adversarial
   test corpus for this path (§9).

## 4. State, idempotency, and the outbox

- **Identity.** A call **order** (`order_id`, issued by the mayor, §5.5) may have several
  **attempts** (`call_id` = ULID per dial). Verdict identity is `order_id + question_id +
  candidate_revision`; it is stable across attempts, so a resumed call cannot produce a second
  "same" verdict with a different key.
- **Event log.** Append-only JSONL per order under the service's state dir (§5.4): `order`,
  `attempt`, `dialed`, `connected`, `consent`, `section`, `asked`, `candidate`, `readback`,
  `confirmed`, `unconfirmed`, `interrupted`, `note`, `outbox_intent`, `outbox_receipt`,
  `ended`, `error`. Every record is fsynced before the service acts on it.
- **Transactional outbox, write-through.** On CONFIRMED (and on every note/queued question)
  the service appends an `outbox_intent` (fsync), then delivers to each sink — `gc mail send
  mayor`, `gc bd comment <bead>` — and appends an `outbox_receipt` per sink. Delivery is
  **at-least-once**: a crash between a sink accepting and the receipt landing causes a
  resend, and every payload carries the verdict key, so the receiver (mayor mail handling;
  the comment text itself) de-duplicates on the key. Mail and comment succeed independently —
  a failed comment is retried without re-sending mail. Mid-call, delivery is asynchronous to
  the conversation; a sink outage never stalls the call. A dropped call therefore loses at
  most the one non-terminal question, never a confirmed verdict.
- **Order-level persistence.** `attempts[]`, per-question terminal states, `resume_allowed`,
  and `redial_scheduled/completed` are on disk, so "at most one" is enforced across service
  restarts, not just in memory.
- **Dropped call mid-verdict.** Every non-terminal question becomes `INTERRUPTED`. **v1 has no
  automatic redial** (default; Afik may enable it, §10.9): the bridge cannot distinguish a
  transport drop from a founder deliberately hanging up, and an unprompted call-back is
  harassment. Instead the founder gets a Slack message: "we got cut off at Q2 — reply 'call
  me' to resume, or answer here." A resume is a new attempt under the same `order_id`, with
  the same brief minus terminal questions ("picking up on PR 21"). Pre-drop partial audio is
  never trusted as a confirm. If auto-redial is enabled later, it fires only on a positively
  classified transport failure (probe `ended` within 3 s of secretary speech and no goodbye
  phrase in the founder's last two turns), at most once, recorded as `redial_scheduled`
  before dialing.
- **Attempt exhaustion.** Outcome `partial`; the remainder goes to Slack; the summary mail
  lists confirmed / unconfirmed / interrupted / never-asked explicitly.

## 5. Security

### 5.1 Who it may call — fail-closed allowlist, and what it does not prove

- The bridge authorizes a dial only when the "Click to Call" surface contains the configured
  handle (digit-normalized) **or a case-insensitive substring of the configured display
  name**, and refuses on zero or multiple matches. The handle check is the strong one; the
  name check is containment, so the configured `targetName` must be the founder's exact,
  distinctive FaceTime display name, and the config must always carry the handle.
- **One founder in v1** (Afik, §10.3) uses the pinned CLI unmodified — one canonical config
  file, 0600. **Multi-founder** requires the small carried patch: a `--config <path>` flag (or
  `FACETIME_BRIDGE_CONFIG`) accepted per invocation, one immutable 0600 file per founder,
  selected by the service from its static founder table (name → handle → config path, also
  0600, host-local, not in any repo). The canonical config is never rewritten in place, and
  the host single-flight lock (§2.2) means two orders cannot race on it.
- The service refuses call orders whose callee is not in the founder table — before any AX
  code runs. Two layers must agree before a dial is attempted.
- **`answer` is present in the vendored artifact and unreachable here.** The pinned CLI and
  Swift helper ship `answer`; the secretary service has no code path that invokes it, and our
  build of the helper carries a one-line patch returning `UNSUPPORTED` for the `answer`
  command so the resident binary cannot auto-answer even if invoked by hand. The ringing
  classifier stays unused. Anyone calling the secretary's handle rings into nothing.
- **Speaker identity is not verified.** A connected call proves the founder's *account/device*
  answered, not that the founder is speaking. Every verdict record carries
  `speaker_verified: false`; irreversible-weight verdicts require the second-channel Slack ack
  before the mayor acts (§3.3). Voice-print verification is out of scope.
- The host's dedicated iCloud identity (§8) is single-purpose; its handle is the caller-ID
  founders save. Nothing else runs under that identity.

### 5.2 What it may say — corpus boundary

The brain's entire knowledge for a call is: the fixed system prompt + the frozen Call Brief +
its own tool acks. No retrieval, no browsing, no filesystem, no gc/bd access, no memory across
calls. The brief is compiled exclusively from designed mayor surfaces (§2.1); if it isn't in
the brief, the secretary cannot say it — the scripted answer to an off-brief question is "I
don't have that — I'll queue it for the mayor" (→ `queue_question_for_mayor`).

### 5.3 Prompt-injection posture for read-aloud text

Brief content can embed text that originated outside the city (Slack messages, PR titles,
commit messages, external email excerpts). Honest capability inventory of a hijacked brain:
it can **say things to a founder** (social engineering — "the mayor says to approve the
wire"), **write durable mail/comments** (spam, misleading notes), and **ask to end the call**.
It cannot execute, cannot mint verdicts for unqueued questions, and cannot confirm a verdict
(the confirm is the service's evaluation of the founder's transcribed turn). Posture:

1. **Service-owned sequencing.** The brain cannot skip or reorder the open-words queue, cannot
   open the next digest section, cannot end the call before sign-off unless the founder's
   transcript contains a goodbye, and cannot speak protocol lines (read-backs are `say`ed by
   the service). Injected text can only colour the improvised digest/open-floor turns.
2. **Quotas and rate limits.** ≤5 notes, ≤5 queued questions, ≤3 candidate revisions per
   question, ≤1 `request_end_call` per minute. Everything over quota is dropped and logged.
3. **Mark and cap at compile time.** External-origin spans are wrapped as quoted data
   (`{origin: "external", text: …}`) and length-capped; long external text is summarized by the
   mayor's own surface pipeline before it reaches a brief. The system prompt says brief
   content is material to read aloud, never instructions. Rendered speech introduces external
   spans as quotes ("the PR title says: …"). Instruction-shaped external content ("ignore
   previous instructions" class) fails compilation with an error the mayor sees — a tripwire,
   not the defence.
4. **Founder-side framing.** The greeting states that the secretary relays and never
   instructs; the mayor's own asks are only ever in the open-words queue, which the founder
   hears as the fixed "Confirming…" grammar.
5. **Adversarial acceptance tests (Phase 1).** A corpus of injected briefs must produce no
   state change beyond notes and no CONFIRMED verdict without a matching founder turn.

### 5.4 Secrets, storage, transport, consent

- **Secrets.** Realtime API key in the service's environment via Infisical (`agents` env),
  never in page source. The browser page gets an **ephemeral realtime client secret** minted
  per call by the service (OpenAI's WebRTC ephemeral-token flow); the long-lived key never
  touches the browser. Provider zero-data-retention settings are enabled where offered.
- **Storage.** The service runs as its own macOS user; state dir 0700, files 0600; FileVault
  on. Event logs and transcripts are retained **30 days** then deleted (Afik-tunable, §10.7);
  no raw audio is retained by default; no backups of transcripts. Bead comments carry only the
  verdict, the confirm transcript, and a ≤200-character answer excerpt — never the full
  transcript. Storage failure is **fail-closed**: no new call starts if the outbox is not
  writable or free disk is below threshold; an in-flight call whose log write fails ends early
  with a scripted "I'm having trouble recording — the mayor will follow up on Slack."
- **Transport.** The bridge page and service speak only on `127.0.0.1` (upstream default
  `127.0.0.1:5612`). The service mints a random per-call **capability token** when it launches
  the browser session; every tool request from the page carries it; it is bound to the
  `call_id` and dies at teardown. Nothing listens on the network; city reaches the service via
  authenticated `gc mail` orders (§5.5), not HTTP.
- **Consent.** Setup-time written opt-in per founder (recorded in the founder table) is the
  primary record; the in-call disclosure + "OK to continue?" is the per-call record (§3.1). The
  founder's audio necessarily reaches the provider from pickup (the secretary has to hear the
  answer); pre-consent transcripts are not persisted, and a refusal leaves only the consent
  event on disk.

### 5.5 Control plane — authenticated call orders

A call order is a `gc mail` from the mayor identity (the service accepts orders from no other
sender, including the CLI, which only *forwards* an order the mayor already issued):

```jsonc
{ "order_id": "01J…",  "issuer": "mayor",  "callee": "afik",
  "purpose": "post-evening-brief",          // or on-demand
  "brief_ref": "briefs/2026-08-27-evening.json",  "brief_sha256": "…",
  "issued_at": "2026-08-27T23:30:00Z",  "ttl_s": 1800,  "nonce": "…" }
```

The service persists seen `order_id`s (replay-safe), rejects expired orders, unknown callees,
and hash mismatches, and answers every order with a receipt mail (accepted / rejected +
reason). The on-demand path is: founder says "call me" in Slack → the mayor issues an order →
the service dials. Founders never talk to the service directly.

## 6. Cost model

as deprecated; `gpt-realtime-2.1-mini` is its replacement) and ElevenLabs' Agents pricing page

service records measured usage on every call summary.

Notes. (1) Realtime sessions re-bill accumulated context each turn; cached-input pricing keeps
that from dominating **only if the context is left stable** — trimming already-read sections
would defeat the cache, so the service does not trim mid-call and relies on the hard caps
(15 min/call, daily call cap, §10.4) to bound the tail. (2) The `2.1-mini` tier has weaker
instruction-following and tool reliability; this design tolerates that because every
protocol-bearing line and every confirm decision lives in the service, not the model, which is
exactly what makes mini viable here. (3) ElevenLabs is competitive on the platform fee but the
LLM pass-through makes its total the least predictable of the three. Fixed costs: FaceTime and
BlackHole are free; the only capex is the optional Mac Mini (§8, ~$500–600 used).
**Recommendation: start on `gpt-realtime-2.1-mini`** (~$15–27/month), upgrade to `2.1` only if
Phase 0 shows quality/latency problems the founders notice.

## 7. Failure modes & supervision

Design stance (from the research): Apple UI changes surface as "unavailable behavior instead
of guessing" — so treat FaceTime as a best-effort channel with Slack/mail as the invariant, and
supervise the fragile legs (browser, audio path, AX, macOS, GUI session, storage) explicitly.

| failure | detection | response |
|---|---|---|
| browser bridge tab dead / second-tab lock refusal / sleep / autoplay denied / muted or stalled track | preflight page-health ping incl. a track-state check; in-call `health` events; launchd keepalive on a dedicated Chromium kiosk profile | restart kiosk; order retries once, then Slack fallback |
| **silent audio path** (FaceTime pickers drifted off BlackHole, device renamed, driver missing — frames arrive but are zeros) | inbound RMS floor within 10 s of greeting; outbound track producing frames; `doctor` device checks; monthly manual picker check | hang up silently, outcome `audio_fail`, Slack fallback, mark degraded |
| AX drift (macOS update changes UI strings / `com.apple.mobilephone` surfaces) | post-update canary: `doctor` + `probe` + supervised test call; dial errors `PROMPT_TIMEOUT`/`AMBIGUOUS_ACTION` | degraded, calls suspended, Slack-only; repair = Bootoshi's own method (place a manual call, re-record the AX tree), documented as a runbook |
| "Click to Call" banner suppressed (Focus mode, notification settings) | `doctor` extension: assert Focus off + notifications enabled for the host identity | host-Mac config item + weekly canary; fail = suspend + alert |
| GUI session locked / logged out; TCC grants (Accessibility, microphone) revoked | preflight: session unlocked check, `AXIsProcessTrusted`, mic permission probe | suspend + alert; never attempt a dial without a live GUI session |
| founder doesn't answer / unreachable | answer deadline in the probe loop (§2.2 step 6) | outcome `unreachable`; digest + questions to Slack; one attempt per order |
| call drops mid-conversation | probe `ended` without service-issued hangup | §4: INTERRUPTED, Slack resume offer; no auto-redial in v1 |
| realtime API outage / degraded | session error; no model audio within 5 s of greeting `say` | service hangs up, Slack fallback, alert |
| service crash mid-call (orphaned live call) | independent watchdog (separate launchd job) probes every 60 s; `connected` with no live attempt record, or attempt older than cap | watchdog runs `facetime-bridge hangup`; alert mail |
| concurrent orders | host single-flight lock (§2.2 step 1) | second order queues with its own TTL; expired orders are rejected with a receipt |
| storage: disk full, unwritable outbox, log corruption | preflight thresholds; fsync errors | fail-closed (§5.4): no new calls; in-flight call ends early with the scripted line |
| Slack fallback unavailable / rate-limited | fallback post fails | durable fallback queue with retry; mayor mail (local) as last resort so the digest is never lost |
| macOS auto-update breaks the stack overnight | auto-update disabled on host; updates are a maintenance procedure | update → doctor → canary call → re-enable |
| cost runaway (stuck session) | 15-min call cap, per-response output limits, daily call cap, measured usage on every summary | forced hangup + alert |

All state transitions (degraded / suspended / recovered) land as mayor mail, mirroring the
advisory-health pattern the slack-full adapter already uses (gp-rol): the secretary reports
its own liveness into city surfaces rather than failing silently.

## 8. Host: citadel vs dedicated Mac Mini (Afik decision — §10.1)

| | citadel (Mac Studio, runs the city) | dedicated Mac Mini + dedicated iCloud |
|---|---|---|
| capex | $0 | ~$500–600 used |
| iCloud | must sign a **new** dedicated identity into FaceTime on the box that runs everything | clean single-purpose identity = clean caller-ID ("Gas City Secretary") |
| Accessibility / TCC | AX-driving binary + mic grant on the busiest machine | blast radius contained to a box that does nothing else |
| notifications | banners must stay ON (load-bearing for dialing) — conflicts with a working machine's DND | banners always on, nobody cares |
| GUI session | must stay logged in + unlocked for AX; conflicts with normal lock policy | dedicated auto-login user, screen never locks |
| audio | BlackHole devices added (per-app pickers only, but present) alongside transcription workloads | audio stack owned entirely by the secretary |
| macOS updates | citadel updates now gated on voice-stack re-verification | update/re-record cycles never touch citadel |
| ops | already supervised, on tailnet, always-on | one more machine to power/network/monitor (tailnet join) |

The research note and the upstream README both point the same way: a dedicated always-on Mac
with a dedicated iCloud account. **Recommendation: dedicated Mini** — it is the structurally
correct host, and the unlocked-GUI requirement alone is a poor fit for citadel. citadel remains
viable if Afik prefers $0 capex and accepts the coupling. Phase 0 can spike on any spare Mac
without committing.

## 9. Phased plan

- **Phase 0 — costed spike (1–2 days, one bead).** Host checklist from the research notes
  (BlackHole casks, dedicated iCloud sign-in + one manual FaceTime call, helper compile with
  the `answer` stub, AX + mic trust, FaceTime device pickers, **all `doctor` facts green**).
  Wire a minimal brain (OpenAI Realtime, `2.1-mini`, scripted greeting + one read-back) and
  place **one supervised test call to Afik**. Deliverables: measured $/call and usage
  breakdown (validates §6), probe-loop cadence, latency/quality verdict on mini vs 2.1,
  go/no-go.
- **Phase 1 — v1 outbound-only (the product in this spec).** Secretary service (controller,
  state machine, outbox, order intake) + mayor-surface adapter + Slack/mail fallback +
  watchdogs + adversarial test corpus (§5.3-5) + runbook for AX re-record. Two triggers:
  (a) post-evening-brief call at the agreed hour; (b) on-demand — founder says "call me" in
  Slack → mayor issues an order → dial within N minutes. First week is supervised: the
  secretary announces each call in Slack ("calling Afik in 2 min: 3 items") before dialing.
  Single founder (Afik) on the unmodified bridge config path.
- **Phase 1b — second founder.** Carried `--config` patch + per-founder configs + founder
  table; Taylor only after the Shanghai FaceTime test (Phase 3).
- **Phase 2 — conveniences (separate design ping, only if v1 sticks).** Founder-initiated
  resume window after a drop, optional auto-redial behind the transport-failure classifier
  (§4), per-founder scheduling preferences, multi-founder same-brief sequencing. Any use of
  `answer` is a Phase 2 design decision, not a flag flip.
- **Phase 3 — CN leg (jadegate/Sinan lane, explicitly out of v1).** Taylor in Shanghai:
  first a live test of plain FaceTime-over-data through the GFW (the research flags it may
  simply work, and it's free to test); only if that fails, a WeCom voice bridge — different
  transport, same brain/brief/verdict layers by design.

Deferred indefinitely: PSTN/Twilio, inbound switchboard, voice-commanded execution,
voice-print speaker verification.

## 10. Decisions reserved for Afik

Defaults in **bold**; nothing below is assumed settled by this spec.

1. **Host**: dedicated Mac Mini (**recommended**) vs citadel (§8) — and the budget if Mini.
2. **iCloud identity**: the handle + display name founders will see ("**Gas City
   Secretary**"?). Must exist before Phase 0's manual test call.
3. **Which founders in v1**: **Afik only** (also what keeps the vendored config path
   unpatched), with written opt-in recorded per founder; Taylor after the Shanghai test.
4. **Call hours + caps**: permitted window per founder (**post-evening-brief slot + on-demand
   within 09:00–22:00 local**), max **2** scheduled calls/day, hard **15 min**/call.
5. **"Call me" trigger surface**: **founders only, in Slack, relayed by the mayor** — the
   service accepts orders only from the mayor (§5.5).
6. **Escalation and authority rules**: what may trigger an *unscheduled* call (**P0 incidents
   only**); and confirmation that **irreversible-weight verdicts need a second-channel Slack
   ack** before the mayor acts (§3.3, §5.1).
7. **Recording/retention**: **transcript + event log only, 30-day retention, no audio**;
   greeting discloses logging and asks "OK to continue?" either way (§3.1, §5.4).
8. **Provider + model for v1**: **OpenAI Realtime, `gpt-realtime-2.1-mini` first** (§6),
   ElevenLabs as the tested alternate.
9. **Redial policy**: **no automatic redial; founder-initiated resume via "call me"** (§4).
   Auto-redial (one attempt, transport-failure only) is available as an opt-in later.
