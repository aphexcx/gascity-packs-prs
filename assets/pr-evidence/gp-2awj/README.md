# Arrival acknowledgements and stopwatch

All channel and Jev checks use fakes. No rollout, live latency measurement or
live WhatsApp reaction-delivery check is included. The gateway is unchanged.

## Design

The catalog stays authoritative: both Go modules embed byte-identical copies,
listed in the catalog parity test; WhatsApp reads its pack's catalog at runtime.
Neutral keys use the original catalog row index. Only arrival rows are offered.
The existing independent acknowledgement path is retained from the earlier
design; keyword rules and the earlier model-specific chooser are replaced by
the catalog and TypeSafe's choice endpoint.

Google uses one shared five-per-second pace for automatic and explicit
reactions. Tests exercise latest-safe scheduling, early usable choices, a lone
timeout, nine simultaneous timeouts, and twelve messages with paced overflow.
Slack and WhatsApp have no local reaction pace. Their channel requests run
independently of delivery and receive no arrival-path retry.

WhatsApp words timestamps follow ruling 1: first observed successful acceptance,
written once by returned message ID. `acceptance_uncertain` distinguishes
confirmed first attempts from confirmation after retry or recovery.

## Named behavior checks

- `TestChoiceCatalogAndRequest`, `TestChoiceTieBreakPairs`,
  `TestChoiceNoTextNoKeyAndCharacterLimit`: request shape, header, catalog,
  neutral options, Unicode, text-only state and both ambiguous pairs.
- `TestChoiceFallbacksAndUnusableCatalog`: malformed/empty catalog, no usable
  arrivals, wrong field types, forbidden fixed modes, 401/422/429/529/500,
  malformed answers and unoffered choices. No retries.
- `TestChoiceDeadlineAndConcurrency`: held vendor, four concurrent requests,
  nine choices completing on the injected deadline.
- `TestAcknowledgementExclusionsAndRestart`,
  `TestAcknowledgementOffStillTimesInbound`: eligibility, durable one-attempt
  behavior, and stopwatch with acknowledgements off.
- `TestArrivalPaceFakeRequests`, `TestArrivalLatestSafeSlots`: ruling 2.
- `TestNineArrivalsDeliverWhileJevIsHeld`,
  `TestNineSlackArrivalsDeliverBesideHeldChoices`, and WhatsApp's
  `nine live deliveries reach gc while Jev holds, with four choices and one reaction each`:
  delivery proceeds while vendor requests remain held.
- `TestArrivalRunsBesideDeliveryAndOwnReactionIsLocal`: Google reaction echo
  stays local and creates no inbound turn.
- `TestArrivalConfigConflicts`, `TestArrivalSlackTwinsAndSessionActs`,
  `TestStopwatchFileSharesUseSlackTime`: Slack mutual exclusions, paired events,
  existing session-act observation and channel file timestamps.
- `TestArrivalEnvironmentPrecedence`, `TestStatusJevKeyIsOnlyPresence`,
  `TestChoiceEndpointAndCanary`, and WhatsApp's
  `canary key is absent from errors and log output; empty text and missing key never call`:
  key precedence and output safety.
- WhatsApp's stopwatch tests cover successful first attempt, lost response,
  retry with and without restart, and repeated confirmation of one message ID.
- `test_stopwatch_exact_text_json_and_copies`: exact report fixtures, release
  grouping, thread isolation, time cuts, nearest rank and torn-line handling.

The sample journal and both report outputs are generated by the report test's
fixture. `jev-request.json` is the request checked by the fake vendor test;
the Authorization header is tested with an invented credential and is omitted
from this artifact.

## Independent review

The first independent review found three major issues, all reproduced before
fixing: missing company-post observation (room, DM, MPIM), a ten-second timeout
that discarded a large paced backlog, and command/service state-directory
disagreement. The fixes reuse authenticated company receipts, start the HTTP
timeout after pacing, and resolve supervised state from command city context.
Regression tests are `TestCompanyConfirmedPostsAreTimed`,
`TestOverflowKeepsEveryArrivalPastTenSeconds`, and
`test_stopwatch_finds_supervised_state_from_command_city`. Visible company
reactions are also timed with arrivals off; words events deduplicate across
restart. No additional session observer was introduced.
