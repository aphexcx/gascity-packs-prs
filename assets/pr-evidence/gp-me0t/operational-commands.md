# Operations outside local verification

The Makefile, package scripts, shell and interpreter entry points, scheduled scripts and Go program entry points were inspected without starting them. The scope below includes read-only tools that would open deployed state or credentials.

| Surface | Entry points and effects |
| --- | --- |
| Chat and issue integrations | The command wrappers, intake or gateway services, scheduled orders, operational doctor checks and their direct script implementations in `discord`, `github`, `gchat`, `slack-full`, `slack-channel`, `slack-mini`, `wecom` and `whatsapp` can read identities, bind channels, consume events, publish, react, upload, open issues or PRs, and query real services. This includes the GitHub identity publisher and resolver examples, Slack replay and measurement tools on real transcripts, and adapter auth, subscription, keeper, gateway and socket checks. |
| Adapter launches | Adapter `run.sh` launchers, the three Slack Go adapter mains, the Slack full CLI, the Google Chat adapter command and the WeCom and WhatsApp Node adapter mains can use configured service endpoints and state. Both Node adapter packages expose a `start` script. A deployed WhatsApp gateway uses Wrangler. Its package build uses Wrangler dry-run and writes a build directory. |
| Board, follow-through and reachability | The board-watcher program and `board-record-write.sh` access boards and record writes. The follow-through CLI, command wrappers, service launcher and scheduled tick can update tickets or notify agents. Reachable's CLI, doctor and command wrappers inspect or change provider hooks, exemptions, modes or live state. |
| City, provider and repository operations | Gas City claim, provenance, bead creation, worktree preparation, Codex gate, credential shim, GitHub App token and GitHub reporting/API scripts use real assignments, providers or API credentials. Gastown's commands and tmux menus, keybindings, theme, status/cycle, churn, heartbeat, PR reconciliation, artifact cleanup and worktree setup operate on sessions, artifacts or Git remotes. The oversight rollup, nudge, escalation, channel resolution and executive-status scripts read or send operational data. |
| Workflow and reporting | The PR pipeline plan, ship, review and blast-radius commands route work. The profiler collection and report commands can read city snapshots. Availability-only doctor scripts that use `command -v` inspect local tools. |
| Runtime and server tools | The Cloudflare installer runs `go install` onto PATH. The runtime provider can call its configured endpoint. The brainstorming server, start and stop scripts in both copies of the superpowers skill manage a real local listener. Generic test drivers such as find-polluter execute the command supplied to them. |
| Release and compatibility | The Makefile targets `registry-publish` and `registry-withdraw` change release metadata. The release binary script can publish with its publish flag. The matching-binary installer, pack release compatibility and pack inference gate invoke installed tools or manage integration fixtures. Registry format and required-Git validation use local history. Release validation can fetch public sources. |
| Optional real-CLI tests | Google Chat rendered contracts opt in through `GC_BIN`. Order scope, shared prompt and live pack composition tests opt in through `GC_TEST_BIN`. Gastown lint may use a gc from PATH to read pack files. Runtime conformance drives an installed gc against a loopback fake Worker. |

### Where to find the operational entry points

- Messaging and issues use the command directories in the eight packs above. Direct paths include `discord/scripts/discord_*service.py`, `github/scripts/github_intake_*.py`, `github/orders/scripts/*.sh`, `github/examples/file_identity_*.py`, `slack-full/scripts/slack_*.py`, `slack-full/scripts/{measure_injected_alerts,replay_minimal_injections}.py`, `gchat/doctor/gchat/run.sh`, `whatsapp/doctor/` and `wecom/doctor/`. Read-only parsers and formatters in these directories can run on supplied fixture data.
- Adapter launchers live at `{gchat,slack-full,slack-channel,slack-mini,wecom,whatsapp}/adapter/run.sh`. Direct entries are the Slack adapter modules, `slack-full/cli`, `gchat/adapter/cmd/gc-gchat-adapter`, `{wecom,whatsapp}/adapter/src/index.js` and `whatsapp/gateway`.
- Board and follow-through use `board-watcher/{watcher,commands/board-record-write.sh}` and `follow-through/{bin/run.sh,commands,orders/scripts/follow-through-tick.sh,src/cli.js}`. Reachable uses `reachable/{reachable.cjs,commands,doctor}`.
- City assignments, credentials, workspaces and GitHub reports use `gascity/commands/{claim,provenance}` and `gascity/assets/scripts/{codex-gate.sh,codex-infisical-shim.sh,create_beads_from_tasks.py,github-app-token.sh,github_api.py,github_reports.py,worker-worktree.sh,worker_provenance.py}`. Gastown uses `gastown/commands/` and its operational scripts under `gastown/assets/scripts/`, including the agent menu, bind-key, cycle and status-line scripts.
- Reporting and routing use `oversight-rig/assets/scripts/`, `oversight-rig/skills/city-executive-status/scripts/`, `pr-pipeline/commands/pr/{plan,ship,review,blast-radius}` and `profiler/{commands,scripts}`.
- Cloudflare uses `runtime-cloudflare/{install.sh,runtime,conformance.sh}`. Brainstorming uses `superpowers/{skills,vendor/superpowers/skills}/brainstorming/scripts/{start-server.sh,server.cjs,stop-server.sh}`.
- Release operations use `scripts/{release-pack-binaries.sh,install_bd_matching_gc.sh,pack_release_compat.py,gascity_pack_inference_gate.py,registry_release.py}` and the two modifying Makefile targets above. The Python validator's hash and entry modes print output.

Fixture tests exercise these code paths with temporary directories, stubs and loopback services. Byte formatting, frontmatter validation, emoji generation from supplied files and a dry-run build do not themselves send messages or deploy anything.
